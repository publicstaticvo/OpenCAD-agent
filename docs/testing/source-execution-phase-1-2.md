# Python 源码编辑与执行验证

## 使用流程

源码工作区提供文件树、可编辑源码、逐次父版本差异和历史快照。用户能够直接运行已保存工程；Agent 使用 `read/write/edit/cad_files/cad_run`。编辑只保存源码，`cad_run` 执行指定快照并自动完成观察与交付检查。成功候选等待用户验收，正式修订在验收后更新。

启动、配置入口和环境变量见 `docs/python-modeling.md`；自动化命令、结果、截图和未执行范围见 `docs/testing/source-workspace-and-activity-timeline.md`。以下人工在线测试全部为 NOT RUN，本轮没有真实模型调用。

## H1–H5 人工在线验收

前置条件：使用已授权在线配置启动应用，新建独立项目。用户只需表达任务目标；不需要输入工具名称。普通请求直接进入 Agent 流程，明确要求计划审批的请求在审批前不编辑源码或执行 FreeCAD。

| 编号 | 用户输入与操作 | 可观察的通过条件 | 本轮结果 |
|---|---|---|---|
| H1 | “创建一个 Python 脚本，使用 Part.makeBox 创建 20×30×40 mm 实体。只保存源码，暂时不要执行。” | 文件出现在源码树且可以打开编辑；活动记录可以打开完整新增行；无执行、候选或正式修订变化 | NOT RUN |
| H2 | “执行刚才保存的源码版本，检查包围盒 20×30×40 mm、体积 24000 mm³，完成后报告执行结果。” | 实际执行记录绑定指定版本；自动检查与预览对应相同执行；有效候选等待验收；用户验收后正式修订更新 | NOT RUN |
| H3 | 分别输入“只修改脚本，将宽度改为35 mm，不执行”和“只修改脚本，将宽度改为45 mm，不执行”；随后要求执行最新版本 | 两次修改分别可查看删除和新增行，父版本准确；编辑期间不执行；最终真实包围盒20×45×40 mm | NOT RUN |
| H4 | 在有效模型后要求保存语法错误，再要求运行；随后要求修复并运行 | 错误源码及差异保留；执行返回 SyntaxError 和位置；失败不覆盖有效模型；修复后产生新的执行及候选 | NOT RUN |
| H5 | 查看活动历史、各次源码差异及执行详情，刷新后再次查看 | 每次工具调用仅有一条更新状态的记录；历史顺序不变；源码、执行、预览和正式修订身份可追溯；不展示模型私有推理 | NOT RUN |

每项记录项目名称、源码版本、执行身份、候选及正式修订、截图与实际错误。用户没有验收前正式修订保持原值是正常状态；没有执行记录或实际几何时不能认定建模成功。

## 自动化证据

`tests/source-gateway.test.ts` 使用实际 Pi 分发和真实 FreeCAD，检查建模任务漏执行提醒、已有源码执行请求、只保存/只读诊断、持续漏执行错误、候选验收及重启恢复。`tests/source-tools.test.ts` 检查实际 Pi 文件工厂、逐次完整快照和文件差异；`tests/e2e/source-execution.spec.ts` 与 `project-workspace.spec.ts` 检查实际编辑器、Diff、运行、候选和正式文件。

上述离线响应序列用于验证框架输入输出和真实 CAD 执行。在线 H1–H5 的模型表现仍需单独记录。
